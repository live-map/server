## 주요 성과

### 1단계: 3단계 검증 파이프라인 (1월 10일)

초기 검증 접근 방식은 순차적 3단계 파이프라인을 사용했습니다:

```
입력 이벤트
    ↓
[Stage 1: NLP 검증]
├── spaCy 엔티티 추출
├── 감정 분석
└── 키워드 감지
    ↓
[Stage 2: API 검증]
├── ClaimBuster API (주장 감지)
└── Google Fact Check API (기존 판정)
    ↓
[Stage 3: LLM 검증]
├── Mistral Small 분석
└── 최종 판정 생성
    ↓
검증된 이벤트
```

### 2단계: RAG 기반 증거 검색 (1월 11일)

API 전용 검증을 Retrieval-Augmented Generation으로 대체:

- **SearXNG 검색**: 멀티 엔진 검색 (Google, Bing, DuckDuckGo)
- **NLI 검증**: BERT NLI 모델로 함의 점수 계산
- **LLM 종합**: 증거 기반 최종 판정

### 3단계: 멀티소스 트리거 시스템 (1월 12일)

Telegram 외의 여러 소스로 데이터 수집 확장:

| 소스 | 유형 | 목적 |
|------|------|------|
| GDELT | 뉴스 API | 글로벌 뉴스 모니터링 |
| Twitter/X | 소셜 | 조기 신호 감지 |
| Telegram | 메시징 | 채널 모니터링 |

### 4단계: 자율 조사 에이전트 (1월 13일)

LangGraph 기반 자율 에이전트 도입:

- **Deep Verification Agent**: 반복적 검색 및 분석
- **Parallel Research Agent**: 동시 증거 수집

### 5단계: Production-Ready v3.0 (1월 14일)

안정화 및 프로덕션 강화:
- 중요 안정성 수정
- 오류 처리 개선
- 재시도 메커니즘
- 속도 제한

## 기술적 결정

| 결정 | 선택 | 이유 |
|------|------|------|
| 검색 엔진 | SearXNG | 자체 호스팅, 프라이버시, 멀티 엔진 |
| NLI 모델 | BERT-base | 빠른 추론, 좋은 정확도 |
| 에이전트 프레임워크 | LangGraph | 상태 관리, 디버깅 |
| LLM 제공자 | Mistral | 비용 효율적, 유능함 |

## 지표

| 지표 | 이전 | 이후 | 변화 |
|------|------|------|------|
| 검증 시간 | 30초 | 15초 | -50% |
| 증거 소스 | 0 | 3+ | 신규 |
| 클레임 세분화 | 이벤트 | 클레임별 | 개선 |
| 데이터 소스 | 1 | 3 | +200% |

---

## 교훈

1. **클레임 수준 검증이 우수함**: 기사 내 개별 클레임 검증이 이벤트 수준 검증보다 더 미세한 결과 제공
2. **증거가 필수**: RAG 기반 증거 검색이 API 전용 검증보다 훨씬 신뢰성 높음
3. **자율 에이전트는 가드레일 필요**: LangGraph 상태 관리가 무한 루프 방지
4. **프로덕션 준비에는 강화 필요**: 초기 개발 후 여러 안정성 단계 필요
5. **멀티소스가 커버리지 향상**: 단일 소스로는 모든 관련 이벤트 포착 불가
