## 요약: 4단계 진화

```
v1 (고정 파이프라인)
 ↓ "유연성 없음"
v2 (자율 에이전트 + RSS)
 ↓ "소스를 내가 정하는 것"
v3 (GDELT 키워드 검색)
 ↓ "GDELT만으론 실시간 안됨"
v4 (다중 소스 + 감지 레이어) ← 현재
```

---

## v1: 고정 파이프라인 (2026-01 이전)

### 구조

```
텔레그램 → Stage 1 (필터링) → Stage 2 (검증) → Stage 3 (판정) → 결과
```

### 문제점

- **유연성 없음**: 새로운 소스 대응 불가
- **고정된 흐름**: Stage 1 → 2 → 3 순서 고정
- **수동 트리거**: 텔레그램 메시지 수신 시에만 작동

### 변경 이유

> "에이전트가 스스로 판단해서 필요한 소스를 찾아야 한다"

---

## v2: 자율 에이전트 + RSS 피드 (커밋 48c3682)

### 구조

```
RSS 피드 (Reuters, BBC, Al Jazeera)
    ↓
키워드 필터 ("war", "protest")
    ↓
LLM 분류
    ↓
자율 조사 에이전트 (LangGraph)
```

### 문제점

- **RSS 피드 = 소스를 내가 정하는 것**
- Reuters, BBC 같은 고정된 소스만 모니터링
- 에이전트가 소스를 "선택"하는 게 아님

### 변경 이유

> "RSS 피드는 출처를 내가 정하는 거 아닌가?
> 진짜 자율 에이전트는 키워드로 글로벌 검색해서 소스를 에이전트가 찾아야 함"

---

## v3: GDELT 키워드 검색 (커밋 523e831)

### 구조

```
GDELT API (100,000+ 소스)
    ↓
키워드 검색 "(war OR protest OR violence)"
    ↓ 소스 지정 없이 전 세계 검색
LLM 분류
    ↓
자율 조사 에이전트
```

### 개선점

- ✅ 소스 하드코딩 제거
- ✅ 100,000+ 글로벌 뉴스 소스 자동 검색
- ✅ 무료

### 문제점

- **GDELT = 뉴스만** (소셜 미디어 없음)
- **15분 딜레이** (실시간 아님)
- 트럼프가 X에 글 올리면 → GDELT는 뉴스 기사 나올 때까지 기다려야 함

### 변경 이유

> "트리거 소스도 다양해야 한다. X든 텔레그램이든.
> 만약 트럼프가 X로 제일 빨리 말하면 GDELT는 뉴스 기사 쓴 거 기다려야 하는 거 아니야?"

---

## v4: 다중 소스 + 감지 레이어 (커밋 86820d2, 2ebb95b) ← 현재

### 구조

```
┌─────────────────────────────────────────────────────────────────┐
│                    다중 소스 트리거                              │
│                                                                 │
│  GDELT (뉴스)  +  X/Twitter (Twikit)  +  Telegram (Telethon)   │
│       │                  │                      │               │
│       └──────────────────┴──────────────────────┘               │
│                          │                                      │
│                   병렬 스캔 + 중복 제거                          │
│                          │                                      │
├─────────────────────────────────────────────────────────────────┤
│                    감지 레이어                                   │
│                                                                 │
│  Layer 1: Keyword Matching (기존)                               │
│           - "war", "protest" 등 키워드                          │
│                                                                 │
│  Layer 2: Anomaly Detection (NEW)                               │
│           - 볼륨/속도 스파이크 감지                              │
│           - 키워드 없이도 "변화" 감지                            │
│                                                                 │
│  Layer 3: Semantic Clustering (NEW)                             │
│           - 새 클러스터 = 새로운 주제 출현                       │
│           - 키워드 없이도 관련 문서 그룹화                       │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                    LLM 분류                                      │
│                          │                                      │
│                    자율 조사 에이전트                            │
└─────────────────────────────────────────────────────────────────┘
```

### 개선점

- ✅ 다중 소스 (뉴스 + 소셜)
- ✅ 실시간 (X, Telegram)
- ✅ 키워드 없이도 감지 (Anomaly, Clustering)
- ✅ 모두 무료 ($0/월)

### 추가된 이유: 감지 레이어

> "키워드 매칭의 근본적 한계가 있다.
> - 'war', 'protest' 키워드에 없는 새로운 유형의 사건은?
> - 암호화된 언어, 신조어는?
> - 예상 못한 방식으로 표현된 사건은?"

**해결책:**
1. **Anomaly Detection**: 볼륨 스파이크 = "뭔가 일어났다" (키워드 무관)
2. **Semantic Clustering**: 새 클러스터 = "새로운 주제 출현" (키워드 무관)
